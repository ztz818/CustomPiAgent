# Nova PPT Lite

目标：用最短、可验证的路径交付可编辑 PPTX。不要先建立复杂 JSON 规格、组件平台或多阶段设计协议；先理解任务，再直接用 OfficeCLI 完成增删改。

## 工具基线

执行 PPTX 任务时，以同级技能 `../officecli-pptx/SKILL.md` 为 OfficeCLI 操作基线；先读取与当前任务相关的章节，不复制它的长篇说明。

它是 OfficeCLI 命令、对象模型、排版要求和 QA 的权威说明。命令或属性不确定时先运行：

```bash
officecli help pptx
officecli help pptx <element>
officecli help pptx <verb> <element>
```

不要猜参数，不要另造 PPT 构建器。

## 第一性原则

1. 用户要的是正确、好看、可继续编辑的 PPTX，不是中间规格文件。
2. 新建或大改时，先列出页面标题顺序；小改时直接定位目标页和对象。
3. 一页只表达一个核心判断，图形负责关系，文字负责解释。
4. 优先复用现有演示稿、用户素材和 OfficeCLI 原生对象。
5. 能小改就不重做，能批量操作就不用重复单条命令。
6. 不编造数据、案例、客户背书或医学结论；缺失信息明确标记。

## 默认视觉主题：中国平安商务橙

用户未提供品牌、模板或明确风格时使用本主题。编辑已有 PPTX 时默认延续原稿；只有新建、重做或用户要求统一风格时才应用平安主题。

### 配色

参考 `drafts/260811/帕金森三项核心服务方案汇报.pptx` 的暖白、橙色和深灰风格：

| 角色 | 色值 | 用法 |
|---|---|---|
| 主橙 | `D75F00` | 关键标题、重点数字、主流程、重点模块 |
| 亮橙 | `EE6F0B` | 小面积强调、图标、状态标记 |
| 浅橙 | `F6B173` | 辅助数据、次级模块 |
| 暖白 | `FDFAF5` | 默认页面背景 |
| 米色 | `EBE7E0` | 分区底、表格底、弱化卡片 |
| 淡橙底 | `FDF3E8` | 重点说明区、图标底形 |
| 主文字 | `262626` | 标题和正文 |
| 次文字 | `4A4A4A` | 正文、图表标签 |
| 弱文字 | `8C8C8C` | 注释、来源、页脚 |
| 白色 | `FFFFFF` | 深色或橙色底上的文字 |

颜色比例：暖白/白色约 65%，深灰约 20%，橙色约 10–15%。不要把整页铺满高饱和橙。

### 字体与排版

- 中文优先：`MiSans`；强调标题可用 `LXGW Bright`。缺失时统一回退到 `Microsoft YaHei` 或 `Arial`。
- 标题通常 36–44pt，正文 18–22pt，说明 10–14pt；每个文本框显式设置字体和字号。
- 16:9 画布，边距至少 1.27cm，模块间距至少 0.76cm，保留约 20% 留白。
- 标题短、左对齐、层级明确；不用装饰性标题下划线。
- 以大标题、关键数字、流程轴、对比结构或语义图标形成视觉锚点。
- 卡片仅用于分组，避免连续页面重复相同卡片墙。
- 默认少阴影、少渐变、少装饰；使用暖白背景、橙色重点、细线和克制圆角。

### 常用页面节奏

按内容选择，不强制套模板：

- 封面：暖白或主橙背景，大标题 + 项目/汇报信息 + 简洁品牌色块。
- 章节页：大号章节编号或关键词，低密度。
- 总览页：一个结论 + 3–4 个结构模块。
- 机制/服务页：流程、路径、分层或前后对比，不用纯文字列表代替关系图。
- 数据页：原生图表 + 明确结论；关键 KPI 直接使用大数字。
- 收束页：结论、行动项、责任人或下一步。

## 轻量工作流

### 1. 判断任务类型

- **读取/分析**：先 `view outline`，需要时再 `view text`、`annotated`、`stats`。
- **小范围修改**：打开原文件，定位页和具名对象，精确 `set` / `remove` / `move`。
- **增删页或结构调整**：先确认页面顺序，再执行 slide add/remove/move。
- **新建或整体改版**：先写标题序列和每页一句话任务，然后直接按展示顺序构建。

### 2. 直接操作

```bash
officecli view "$FILE" outline
officecli open "$FILE"
# add / set / remove / move / batch
officecli save "$FILE"
```

规则：

- 自定义设计使用 `layout=blank`。
- 新对象创建时设置稳定、语义化的 `name`，后续优先用 `@name=` 选择。
- 结构操作后先 `get "/slide[N]" --depth 1` 再继续。
- 重复卡片、图标行、流程节点优先使用 `officecli batch`。
- 保留文字、表格、图表、形状、连接线为原生可编辑对象；禁止把整页做成截图。
- 图片和 SVG 必须写 `alt`；内容页按需要添加 speaker notes。

### 3. 最小 QA

每次交付至少执行：

```bash
officecli save "$FILE"
officecli validate "$FILE"
officecli view "$FILE" issues
officecli view "$FILE" text
```

检查：

- 无结构错误、越界、裁切、无意义重叠。
- 无 `TODO`、`lorem`、占位符和空图表标题。
- 字号、颜色、间距和对齐一致。
- 深色/橙色底使用高对比文字。
- 流程连接线有方向箭头。
- 页数、顺序和用户要求一致。

如果本机已有可用渲染器，抽查或逐页截图进行视觉审阅；截图首次失败就停止，不安装浏览器或大型依赖，并在交付时说明视觉验证受限。

## 矢量图标

默认图标库：`assets/icons/tabler-outline/`。它用于语义定位和流程表达，不用于装饰性撒图标。

检索示例：

```bash
find .pi/skills/nova-ppt-skill/assets/icons/tabler-outline \
  -type f \( -iname '*health*.svg' -o -iname '*heart*.svg' \) | head
```

使用规则：

1. 同一页、同一组并列项使用同一图标家族、相同尺寸、线宽、底形和颜色。
2. 图标优先使用主橙 `D75F00` 或主文字色 `262626`。
3. 需要改色时，在任务素材目录生成副本，不修改图标源文件：

```bash
mkdir -p drafts/YYMMDD/<task-name>/assets
sed 's/currentColor/#D75F00/g' source.svg \
  > drafts/YYMMDD/<task-name>/assets/icon-name.svg
```

4. 通过 OfficeCLI 作为 SVG picture 插入，保持矢量质量，并设置准确 `alt`。
5. 找不到合适图标时，优先用 OfficeCLI 原生形状和连接线组合；不要使用 emoji。
6. 品牌 Logo 使用用户提供的官方矢量文件，不用通用图标冒充。

## 增删改操作重点

### 改文字或样式

先 `get` 确认对象，再 `set`；不要通过删除整页重建来修改一句话。

### 增页

明确新页插入位置、页面任务和与前后页的叙事关系。增页后复查页码、章节和内部跳转。

### 删页

删除前确认该页是否被目录、Zoom、超链接或备注引用；删除后复查顺序。

### 重排与改版

优先保留事实内容和可复用对象，只调整层级、坐标、尺寸、配色和关系图。除非用户要求，不改变原意或擅自扩写。

## 交付

默认只交付用户需要的最终 `.pptx`。如果任务产生了 SVG、图片等必要素材，一并保存在任务目录。除非用户明确要求，不额外生成 deck-spec、设计协议、组件目录或长篇报告。

最终说明保持简洁：文件路径、完成的主要修改、QA 结果、仍存在的限制。
