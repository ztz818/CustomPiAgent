# Nova PPT

Nova 把源材料转化为结构完整、视觉统一、可以直接交付的原生 PowerPoint。目标不是机械套模板，而是用一套受控的视觉系统讲清楚一个完整论点，并生成可继续编辑、修改和演示的 PPTX 文件。

## 必须达到的结果

每次交付都必须满足：

- 生成原生 16:9 PPTX，不以整页截图作为主要页面结构。
- 文字、形状、表格、图表、图片和演讲者备注可分别编辑。
- 全篇只有一条叙事主线、一套设计系统，并根据页面角色有节奏地变化构图。
- 每页都有清晰的视觉锚点和图形骨架；图形不是文字的装饰背景，而是帮助受众理解关系、顺序、规模或重点的第二种语言。
- 完整度和视觉质量接近专业商业汇报，而不是只有标题和几个文本框。
- 文件结构校验通过，版面问题经过检查，没有未处理错误。
- 不编造事实；未知内容标为假设或直接省略。

## 执行入口

所有页面先写成 `deck-spec.json`，再由内置构建器生成：

```bash
if [ ! -d .venv ]; then
  UV_CACHE_DIR=./uv_cache uv venv --python 3.11
fi
UV_CACHE_DIR=./uv_cache uv run python \
  .pi/skills/nova-ppt-skill/scripts/nova_ppt_cli.py build \
  --spec <deck-spec.json> \
  --output <presentation.pptx>
```

迭代过程中先检查规格：

```bash
UV_CACHE_DIR=./uv_cache uv run python \
  .pi/skills/nova-ppt-skill/scripts/nova_ppt_cli.py lint \
  --spec <deck-spec.json>
```

## 强制工作流

### 1. 明确沟通任务

从用户要求和材料中提取：

- 受众是谁
- 现场讲解、自主阅读还是混合使用
- 希望受众看完后做什么
- 一句话核心结论
- 已有证据和缺失证据
- 页数、语言、品牌、保密、截止时间等约束

如果用户提供参考演示稿，先提取它的页面角色、标题锚点、分区方式、图标/线条语言、色彩比例、间距和对象层级。参考稿要被转译成可复用的视觉语法，而不是只读取文字；至少挑选封面、结构页和高密度页各一张作为构图样本。


### 2. 先搭故事，再搭页面

先形成紧凑的演示结构：

- 开场判断
- 3 到 6 个支撑章节
- 证据或运行机制
- 决策、行动或下一步

每页只承担一个沟通任务。页数服务于论证，不服务于模板配额。

必读：[内容架构](references/content-architecture.md)。

### 3. 锁定视觉系统

从 [风格目录](templates/style-catalog.json) 选择一种风格，或定义同等完整的自定义系统。必须锁定：

- 背景、正文、弱化、强调、辅助、边框颜色
- 标题、正文、数据、标签、脚注字号角色
- 图标家族和处理方式
- 圆角、线宽和间距尺度
- 跨页重复的页眉、页码和标识

风格目录决定“全篇长什么样”。如果内容是医疗健康、服务方案或老板汇报，优先从风格目录里找到最接近的系统，再微调，不要每页重新发明颜色和字体。

不要逐页更换视觉身份。变化的是构图，不是品牌语言。

必读：[视觉系统](references/visual-system.md)。

### 4. 分配页面角色和布局

在放置对象之前，为每页指定角色。使用 [布局目录](templates/layout-catalog.json) 和 [布局模式](references/layout-patterns.md)。

`layout-catalog.json` 只负责“骨架位置”：标题、视觉区、卡片区、流程区、表格区、结论区在哪里。`layout-patterns.md` 负责“骨架怎么长出来”：什么页该用主张、三部分模型、流程、时间线、数据页或决策页。两者要一起看，先选角色，再选布局，不要反过来。

先画页面的“视觉骨架”，再填文字。视觉骨架至少要回答一个问题：这页的关系、方向、层级、变化或重点，受众靠什么图形一眼看懂？根据页面任务选择并真正绘制对应结构：

- 主张页：一个大结论 + 一个主视觉构图，例如大色块、路径、中心节点、对照关系或关键数字。
- 三部分模型：三个等尺寸模块，每个模块包含独立图标、标题、短描述和共同的连接/底座；不要把三段长文塞进三个圆角矩形。
- 流程页：用节点、连接线、箭头和阶段标签表达方向；文字只解释节点，不承担整条流程的绘制工作。
- 时间线：用主轴、里程碑、阶段色和交付物建立时间推进，不要只做三张并排文字卡片。
- 数据页：优先用原生图表、数据条、比例、指标对比或坐标关系，数字旁边必须有视觉参照。
- 决策页：用“建议—依据—风险—行动”的视觉层级收束，不要把决策点做成普通列表。

硬性创作要求：

- 每页先确定一个第一眼焦点，其他内容围绕它退居二级。
- 每个内容页至少安排一种独立视觉语言：图标、流程线、节点、箭头、数据图形、原生表格、示意图或主题图片；不能让一页只有文字框和文字卡片。
- 图标必须承担语义，不是随机装饰。三项并列服务使用同一图标家族、同一尺寸、同一底形和同一对齐线。
- 卡片只用于分组或承载重复结构。卡片外必须有页面级关系，例如主轴、路径、分区、对比标准或汇总结论。
- 不要把所有信息均匀铺满画布。留出明显的视觉主次、空白和阅读方向。
- 连续三页不能重复同一种卡片墙；应该在主张、模型、流程/时间线之间改变构图，但保持颜色、字体、图标和间距系统一致。

完整演示通常需要密度交替：

- 低密度视觉开场
- 中密度结构解释
- 高密度证据或对比
- 中密度流程或机制
- 低密度综合判断或决策

禁止整套演示全部做成同样大小的卡片墙。

### 5. 准备素材

素材优先级：

1. 用户提供的品牌素材和事实素材
2. 原生形状、表格、图表和连接线
3. 内置矢量图标
4. 主题确实需要真实视觉证据时使用生成图或来源明确的图片
5. 只有能解决层级、聚焦或构图问题时才使用装饰效果

素材要参与版式，不要在最后才贴图标。先为每页列出视觉对象清单：主视觉、结构线/节点、图标、数据表达、辅助标识；再把文字绑定到这些对象上。需要说明关系时优先用原生形状和连接线，需要说明概念时使用同一图标家族，需要说明真实场景时才使用图片。图标优先作为独立可替换对象导入，并配合圆形底、编号、状态色或连接线形成视觉系统。

图标用于语义定位，不用于撒满页面。一套演示只使用一个通用图标家族，品牌标志除外。

必读：[素材系统](references/asset-system.md)。

### 6. 先完成设计协议，再写页面规格

必读 [设计协议](references/design-protocol.md)。先在规格中写全篇 `design` 和每页的 `layout_id`、`visual_job`、`visual_anchor`、`asset_plan`、`text_budget`，再写坐标和对象。

如果提供参考 PPTX，必须先提取结构和视觉语法，记录参考页码和借鉴规则。不能只读取参考稿文本，也不能把三页任务机械拆成三个产品页。

图标必须先用 CLI 检索真实文件：

```bash
UV_CACHE_DIR=./uv_cache uv run python \
  .pi/skills/nova-ppt-skill/scripts/nova_ppt_cli.py icons \
  --family <icon-family> --query <semantic-keyword>
```

`asset_plan.icons` 中列出的图标必须在 `elements` 中以 `type: "icon"` 出现；图标、主视觉、连接线和节点要在填入正文之前完成规划。

### 7. 编写页面规格

规格必须遵循 [页面规格说明](references/deck-spec.md)、[设计协议](references/design-protocol.md) 和 [JSON Schema](schemas/deck-spec.schema.json)。


不可妥协的规则：

- 对象使用稳定、可读、语义明确的名称。
- 坐标和尺寸显式给出。
- 重要文字必须保留为原生文字。
- 行列数据必须使用原生表格。
- 需要后续编辑数据时使用原生图表。
- 现场演示页应增加演讲者备注。
- 图片和图标必须有有效替代文本。
- 重复结构使用一致的尺寸和间距。

### 8. 构建和检查

先运行 `lint`，再运行 `build`。构建器会创建 PPTX、校验文件结构、扫描版面问题并输出统计信息。

渲染环境可用时逐页查看预览，检查：

- 文字裁切或溢出
- 无意义重叠
- 对齐漂移
- 对比度不足
- 信息密度过高
- 字号和字体不一致
- 字体不可用
- 素材缺失
- 构图过度重复

必读：[质量门](references/quality-gates.md)。

### 9. 交付

交付内容包括：

- 最终 `.pptx`
- `deck-spec.json`
- 生成的素材目录
- 校验结果和仍存在的限制

文件存在不等于任务完成。

## 反模式：必须主动避免

- 纯文字页：标题 + 副标题 + 三个圆角矩形，不算完成的视觉设计。
- 卡片墙：所有模块同色、同宽、同高、同权重，页面没有主次。
- 伪图形：用长句描述流程、闭环或层级，却没有节点、箭头、连接线或空间关系。
- 贴图标：在页面最后随机放几个图标，图标与内容、颜色、基线和阅读方向没有关系。
- 视觉漂移：每页单独选颜色和组件，导致封面、内容页和结尾像不同模板。
- 文字搬运：把报告段落缩小后塞进 PPT；应先提炼判断，再用图形承载关系，最后补充短句。


1. 沟通先于装饰。
2. 幻灯片是固定画布，不是自动流动的文档。
3. 可编辑性是产品要求，不是附加技术指标。
4. 每个对象必须承担信息、层级或导航价值。
5. 一致性来自固定角色和重复测量，不来自复制同一个版式。
6. 丰富感来自构图、对比、字体、素材和跨页节奏，不来自堆叠特效。
7. 选择能保留意义和编辑模型的最简单表达。

## 阻断交付的情况

出现以下任一情况必须修复：

- 页面存在未处理的溢出或重叠
- 引用了缺失或不支持的素材
- 在没有原样复刻要求时，正文字号小到无法阅读
- 出现无依据的结论或数字
- 页面数量与页面清单不一致
- PPTX 文件结构校验失败
- 主要页面被扁平化成整页图片
- 全篇没有明确的结论、决策或下一步
