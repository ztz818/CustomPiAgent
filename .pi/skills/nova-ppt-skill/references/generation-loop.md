# 生成循环

Nova 的目标不是把材料填入一个版式，而是在约束下做一次完整的演示设计。每次任务都必须经过以下阶段；阶段之间不能跳过，也不能用构建成功替代设计判断。

## 阶段 A：任务契约

先写出一页任务契约，至少回答：

- 受众是谁，他们已有多少背景知识？
- 演示场景是现场讲解、自主阅读、投屏展示还是打印分发？
- 用户希望受众产生什么变化：理解、相信、比较、决策、行动或学习？
- 页数、比例、语言、品牌、数据来源、编辑要求和交付限制是什么？
- 哪些内容是事实，哪些是建议，哪些是未知？

把“用户要求的内容”与“适合放在页面上的内容”分开。材料中的段落、过程记录和背景信息不应自动成为页面正文。

## 阶段 B：内容压缩与叙事

从源材料提取事实，不直接复制段落。为每个候选页面写：

```text
页面结论：受众看完后应该记住的完整句子
支撑证据：最多 3 组事实、数字或机制
视觉关系：受众需要看懂的顺序、比较、层级、规模或因果
页面职责：这一页不负责什么
```

根据任务选择叙事原型，或组合多个原型。不要因为页数是 3、5 或 10 就套用固定节奏；页数只限制论证容量，不决定页面角色。每页只能有一个主要沟通任务，若一页同时承担背景、机制、计划和结论，必须拆分或明确主次。

## 阶段 C：参考稿转译

有参考稿时，参考稿提供视觉语法，不提供内容模板。至少选择不同角色的样本页，记录：

- 标题锚点、内容安全区、主要留白区和视觉重心。
- 页面中主视觉、支撑结构、证据和脚注的面积比例。
- 颜色的角色和占比，而不是只抄取颜色值。
- 字体角色、字号层级、行距和短句长度。
- 预设几何、自定义几何、表格、图表、连接线和图片各自承担的任务。
- 哪些元素跨页重复，哪些元素随页面角色变化。

参考稿分析的输出必须包含“借鉴什么”和“不借鉴什么”。例如可以借鉴标题锚点和色彩角色，但不应因为参考稿有三列就把所有新内容做成三列。

## 阶段 D：视觉草图

在写任何对象坐标前，为每页写一个与具体业务无关的视觉草图：

```text
第一眼焦点：一个对象或一个对象组
阅读路径：从哪里开始，经过什么，落到哪里
主视觉：主轴、关系图、对比面、数据图、场景图或自定义构图
支撑层：最多 2-4 个次级对象组
空白策略：哪些区域必须保持安静
文字策略：哪些文字成为标题/标签，哪些只进入备注
```

用“删除正文测试”检查草图：隐藏正文后，页面仍应能看出重点、方向和关系。若只剩一堆色块或卡片，说明视觉骨架没有成立。

草图可以是流程、时间线、地图、矩阵、表格、图表、场景、对照、层级、单一大数字或完全自定义构图。不要把“必须有图标”误认为“必须有视觉设计”。

## 阶段 E：设计到对象的映射

为每个视觉组建立对象清单，再写 `deck-spec`：

- 主视觉组：哪些对象构成，哪个对象是主层，哪个对象是辅助层。
- 关系组：连接线、箭头、编号、状态、方向和终点如何表达。
- 证据组：数字、表格、图表或短句如何支撑结论。
- 资产组：图标、图片、品牌标志或自定义几何各自为什么存在。
- 文本组：标题、结论、标签、正文、注释和脚注分别独立成对象。

对象的数量没有固定目标。少量对象可以形成强构图，大量对象也可以形成高密度信息图；关键是每个对象都有信息、层级或导航职责，而不是为了达到数量而堆形状。

## 阶段 F：四层验收

依次检查，不要混为一个“通过”：

1. 内容验收：页序、结论、证据、数字和用户要求是否正确。
2. 结构验收：每页是否只有一个主要任务，信息关系是否可扫描。
3. 视觉验收：先根据设计计划、对象层级、文字预算和结构视图检查焦点、比例、空白、字体层级、颜色角色、图形语言和跨页节奏；环境已有可用渲染器时再用截图增强验证。
4. 技术验收：PPTX 结构、对象可编辑性、字体、素材、溢出和重叠是否正常。

`officecli validate` 和 `officecli view issues` 只覆盖技术层的一部分，不能单独证明审美通过。截图属于可选增强：仅使用环境已有能力，最多尝试一次；失败后标注“视觉验证受限”并停止，未经用户同意不得安装浏览器或切换多条渲染链路。

## 阶段 G：定向返工

发现问题时按问题类型返工：

- 内容不对：回到阶段 B，不改坐标掩盖问题。
- 结构拥挤：回到阶段 B 或 C，删内容、拆页或换视觉关系。
- 视觉平：回到阶段 D，重画主视觉，不是随机增加图标和阴影。
- 层级乱：回到阶段 E，拆分对象并重设字体、尺寸和颜色角色。
- 技术错误：修复规格或构建器，再重新完成视觉检查。

每次返工只解决一类主要问题，并记录尚未验证的层级。
